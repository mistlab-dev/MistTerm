# MistTerm 1.3.0

## What's New

- **The next launch explains the last exit**: If the previous run left a crash report, MistTerm shows it once on startup, with the version, time, and the first line of the error. From that notice you can open the reports folder or copy the full text.
- **An unclean exit is mentioned even when there is no new crash report**: The first install does not prompt. After that, if the last run did not exit cleanly and no new crash report was written (for example the process was force-quit), the next launch still says so once. A later clean exit does not prompt.
- **A disconnect stays visible in the terminal**: When a connection drops unexpectedly, the active tab keeps a banner at the top, with Reconnect and Close. If auto-reconnect is on, the banner shows the attempt count and the wait. Keystrokes during the outage stay on this machine, and you can confirm whether to send them after reconnecting.
- **Output-trigger rules can be edited in the app**: Open Tools → Rule Manager… → Output Trigger. Until you customize them, MistTerm keeps using the built-in rules and does not write a config file. After you save, the next line of output uses the new rules. An invalid regular expression is reported and is not used for matching.
- **Signed-in host lists can sync across devices**: Syncing session passwords and credentials is off by default. When you turn it on, they are encrypted with the sync passphrase you set (Argon2id) before upload, and the server stores only ciphertext. Credentials on another machine open with that passphrase or the recovery code. The local device_key cannot unwrap them. Keep the passphrase and recovery code yourself. If both are lost, the cloud copy cannot be opened, and data on this machine is left in place.
- **Help can open the report folders**: Help → Diagnostics opens the crash reports folder and the hang reports folder.
- **Security-key sign-in**: A session can use a FIDO2 / security key. Signing stays in the system ssh-agent. MistTerm asks you to touch the key or enter the PIN, and explains a cancelled touch, a wrong PIN, or a missing key in plain language.
- **Return to the same remote session after connecting**: When editing a session you can set an optional restore command (for example to reattach tmux or screen). It runs once after a connect or auto-reconnect, when the shell is ready. Leave it empty and nothing runs. A command that had not been sent yet is dropped when the connection drops.
- **Send sequences**: Save several lines of typing as a named sequence and send them, in order, into the current connected pane. You can set a fixed pause between lines. Sequences are separate from command snippets, and they are not sent to other sessions.
