## New

- **Move over from Xshell / FinalShell**: **Terminal → Import from Xshell / FinalShell…**, pick their sessions folder, preview, and import the ones you want. Hosts, groups, ports and user names come along, and passwords too when they can be read. For a session that came without a password, right-click it, choose **Edit** and fill it in.
- **Open ssh:// links from web pages in Mist** (Windows and Linux): in **Preferences**, find **ssh:// links in the browser** and click **Open with MistTerm**. A server you have already saved connects right away; a new one opens the new-session window with the address filled in, so you only add the password. The Windows installer also offers this as an option.
- **A separate Linux build of the `mist` command line**: it runs as-is on older systems (CentOS 7, Rocky 8/9, Ubuntu 20.04/22.04, Debian 12) and on ARM servers, without any desktop components. On a server, `curl -fsSL https://mistlab.dev/install | bash` picks the right one. The Mist desktop app's system requirements are unchanged.
- **Let AI assistants such as Codex or Claude Code check servers with `mist exec`**: `mist exec` now checks commands the same way the desktop app does. Commands that only look run straight away; commands that change the server need your confirmation (or `--yes`); commands your team's rules forbid are refused. Every command is recorded in the audit log. See the manual page on letting AI assistants use mist.

## Improvements

- **Fewer questions while troubleshooting in the AI Assistant**: Mist recognises look-only commands (reading logs, processes, disk usage and so on) more accurately. Tick the box in a plan and Mist stops asking about that kind of read-only command for the rest of this troubleshooting session. Commands that change the server still ask every time.
- **"Use in terminal" / "Apply to terminal" no longer press Enter for you**: the command is put on the input line, and you press Enter once you have read it. Multi-line commands are copied to the clipboard instead.
- **The confirm window shows the rule's name**: when a command needs confirmation, the window shows which rule matched (for example "Confirm before restart (team rule)") instead of an unreadable ID.

## Fixes

- **One-click update on Windows failed**: it could stop with a "No permission to write" error and leave a temporary file in the program folder. Fixed. To go back to the previous version after an update, run `mist update --rollback`; this now also works for the Windows installer edition (the default "install just for me").
- **Clicking a snippet's title skipped the command check**: in the Snippets panel, clicking a title ran the command without your team's command check. It now goes through the same check as everywhere else: blocked commands are blocked, and ones that need confirmation ask first.
- **"Server-side audit unavailable" shown by mistake**: when you connected by IP address but the server's audit agent was registered by host name, this notice appeared even though everything was fine. Mist now recognises the server correctly. New team command rules also take effect right after Mist starts, instead of a few minutes later.
- **The audit agent install window showed the wrong command**: it showed the command that installs the `mist` command line, not the audit agent. It now shows the right one.
