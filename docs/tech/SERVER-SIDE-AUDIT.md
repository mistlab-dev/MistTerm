# 服务器侧命令审计 · 客户端对接说明

> 版本：v1.0
> 日期：2026-08-10
> 写给：MistTerm 客户端开发者
> 关联：本文档描述「服务器侧强制审计」中**客户端需要配合做的部分**。
> 参考现状：`docs/tech/COMMAND-AUDIT.md`（客户端本地判定，现行为）。

---

## 1. 背景

MistTerm 服务端正在落地「**服务器侧强制命令审计**」：在被审计的远程服务器上部署透明 agent，命令在服务器本地执行前会回调服务端判定/记录。

**关键变化（信任边界）：**
- 命令审计的**判定权威**从「客户端本地」移到「服务端 + 服务器侧 agent」。
- 客户端**不再承担信任边界职责**，仅做体验辅助。

**客户端定位调整：**
- 原来的「客户端本地命令审计」（`CmdAuditEngine`，见 COMMAND-AUDIT.md）**保留**，但定位降级为「本地快捷提示」，**不作为安全承诺**。
- 客户端**新增**：展示「服务器侧下达的判定结果」。

---

## 2. 客户端需要做的（本次改动）

### 2.1 展示服务器侧判定结果（核心新增）

当命令被服务器侧审计拦截/告警时，客户端应展示服务器下达的结果：

| 服务器返回 action | 客户端表现建议 |
|------------------|---------------|
| `block` | 展示「该命令被服务器策略禁止」提示（可含命中规则 message） |
| `confirm` | 展示「服务器侧要求确认」的提示/交互 |
| `alert` | 展示「该命令已上报团队审计」的轻提示 |

- **触发方式**：命令在服务器侧执行失败或被拦时（可从 `record` 回传的 action 感知，或执行后服务端下发结果）。
- **展示形态**：沿用现有通知/toast 样式（参考 `src/ui/app_notifications.rs`），不改变主流程。
- **可叠加**：与本地 `CmdAuditEngine` 的提示叠加展示，但明确来源（本地提示 vs 服务器侧策略）。

### 2.2 调整本地审计定位文案

- `src/core/cmd_audit.rs` 本地判定的文案/命名，避免「安全审计」这类会让用户误以为是强制安全边界的表述，改为「本地快捷提示」语感。
- **不改变功能逻辑**（本地 block 仍拦截、confirm 仍确认），只调整定位与文案。

### 2.3 不建议新增

- **不新增**客户端侧的审计采集/上报信任逻辑（避免重复造信任层）。
- 客户端上报 `/command-audit/alerts` 可保留，但服务端落库标 `source=client`，**以服务器侧为准**。

---

## 3. 客户端需要了解的服务端接口（供参考，不一定全部直连）

| 接口 | 方法 | 鉴权 | 用途 |
|------|------|------|------|
| `POST /v1/server/command-audit/check` | 服务端判定 | agent key | 包裹脚本调用，客户端通常不直连 |
| `POST /v1/server/command-audit/record` | 执行回传 | agent key | 包裹脚本调用，客户端通常不直连 |
| `GET /teams/:team_id/command-audit/alerts` | 查询告警 | 用户 JWT | 客户端可查团队审计（现有） |

> 客户端主要工作是**展示**服务端/服务侧已发生或要求的判定结果，而非主动发起审计。

---

## 4. 验收标准（客户端侧）

1. 服务器侧返回 `block`/`confirm`/`alert` 时，客户端有相应提示展示（来源标注明确）。
2. 本地命令审计功能行为不变，文案定位更新。
3. 不影响终端渲染与命令发送主流程。

---

## 5. 依赖服务端进度

- 客户端「展示服务器结果」依赖服务端 `check`/`record` 落地并返回可识别结果。服务端实施见《命令审计服务端_实施文档.md》。
- 在服务端完成前，客户端可先完成 2.2（文案定位调整），2.1 待服务端接口就绪后对接。

---

## 6. 涉及文件（客户端）

| 文件 | 改动 |
|------|------|
| `src/core/cmd_audit.rs` | 文案定位调整；新增服务器结果解析/展示逻辑 |
| `src/ui/app_notifications.rs` | 复用通知展示（如需要新增类型） |
| `src/core/team/client.rs` | 如需要查询服务器判定结果，增加调用 |

> 详细改动以客户端开发者实际实现为准，本文档仅明确意图与边界。
